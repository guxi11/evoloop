# evoloop

This machine's AI CLIs are rendered from one config repo by `evoloop`.
Every target directory it manages — `~/.claude`, `~/.codex`, `~/.codebuddy`,
`~/.gemini` and the rest of `evoloop targets` — is **build output**: generated
files carry a `GENERATED by evoloop` banner and the next sync overwrites them.

**Never edit a target directory to change behaviour. Edit the config repo, then sync.**

## 1. Find the config repo

Every sync stamps the repo path into the manifest of each target it wrote:

```bash
node -p "require(require('os').homedir()+'/.claude/.evoloop-manifest.json').root"
```

If `~/.claude` has no manifest, try the root of any other target — `evoloop
targets` lists them all.
`cd` into that path before doing anything else.

If no target has a manifest, this machine has no config repo yet — offer to
create one: `evoloop init <dir>` scaffolds it, then `evoloop sync`.

## 2. Edit the right file

| to change | edit | rendered to |
|---|---|---|
| standing instructions, always in context | `rules/*.md` | `CLAUDE.md` / `AGENTS.md` / `CODEBUDDY.md` / `GEMINI.md` |
| a capability loaded on demand | `skills/<name>/SKILL.md` + bundled files | `<target>/skills/` |
| a slash command | `commands/<name>.md` | `<target>/commands/` (`prompts/` on codex) |
| a subagent | `agents/<name>.md` | `<target>/agents/` |
| an MCP server | `mcp.json` | each target's settings file |

Rules are concatenated in sorted path order — one file per concern, named so the
order reads well. Skills follow `skills/<name>/SKILL.md` where the directory
name is the skill name.

Restrict any document to some targets with frontmatter; absent means all:

```yaml
---
targets: [claude, codex]
---
```

## 3. Sync

```bash
npx evoloop status              # what the repo contains
npx evoloop sync --dry-run      # what would change
npx evoloop sync                # render into every installed target
```

Then show the user `git diff` and let them commit. Targets not installed on this
machine are skipped, never created.

## Bringing agent-authored work home

A skill written directly into `~/.claude/skills/` is untracked: sync will not
destroy it, but nothing carries it back to the repo either.

```bash
npx evoloop adopt --dry-run     # list everything no repo tracks
npx evoloop adopt               # copy it into the config repo
```

Run this whenever a session created a skill, command or MCP server in place —
then `sync` and review the diff. Adopt is safe at any time: the bytes already
match, so the following sync is an ownership handoff, not a rewrite.

## Sedimenting a skill from a session

When the user asks to turn what just happened into a reusable skill, write it as
`skills/<name>/SKILL.md` in the config repo — not into `~/.claude` — then sync.
Keep the frontmatter `description` written for retrieval: name the trigger
phrases a future session would actually use.
